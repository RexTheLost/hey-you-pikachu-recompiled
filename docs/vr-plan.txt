HEY YOU, PIKACHU - QUEST VR PORT (TRUE 3D)
==========================================
Decided 2026-11-26: Quest standalone, true 3D (you stand inside the game world).

HOW IT WORKS
- The game hands RT64 (the renderer) every 3D scene with its own camera.
  RT64 already has a debug "free camera" hook that swaps out that camera for
  each 3D scene (render/rt64_projection_processor.cpp). The VR camera uses
  the same spot:
    eye view = game camera, then the headset's head pose, then the eye offset
    eye projection = the headset's own field of view for that eye
- Each frame is drawn twice, once per eye, into OpenXR images instead of the
  phone screen.
- RT64 already draws in-between frames at the display rate. Head tracking
  can run at 72/90 Hz while the game itself runs at about 20-30.
- 2D parts (text boxes, Oak's portrait, menus, the word list) are flat
  (orthographic) layers. They go on a floating panel in front of you instead
  of being glued to your eyes.
- Quest controllers become the N64 pad, read through OpenXR:
    stick = stick, A/B = A/B, trigger = Z (talk), menu = Start
  The headset mic replaces the phone mic; the voice code stays the same.

KNOWN RISKS (true 3D)
1. Culling. The game only draws what its own camera can see, using its
   narrow N64 field of view. Quest shows about 100 degrees per eye, so
   things at the edge of your view may be missing. Fix: find the game's
   cull check (Ghidra) and widen it.
2. Camera motion. The game moves its camera on its own (cutscenes, pans).
   With your head inside that camera, sudden moves can cause motion
   sickness. Plan: smooth or limit the game's yaw, and add an option to
   lock the horizon.
3. Scale. N64 units need converting to metres so Pikachu is about
   40 cm tall. The model rip gives his real size.
4. Backgrounds. Skies and other backdrops drawn as flat 2D rectangles stay
   flat. That's fine in the distance, odd up close.
5. Vulkan device. OpenXR has to approve the Vulkan device RT64 creates.
   That needs a patch to RT64's Vulkan layer (plume) so it takes OpenXR's
   device and extensions.

MILESTONES
M1 PC test bed: an OpenXR build on Windows (Vulkan), run with the Meta XR
   Simulator (D:\AI\tools\meta-xr-simulator). Stereo 3D with head look,
   tested on the PC before any headset time.
M2 Quest APK: the same code through the Android build. Uses the Khronos
   OpenXR loader (already on D: from Angel's Table), a VR manifest
   (com.oculus.intent.category.VR) and controller input.
M3 2D panel: text boxes, menus and the word list on a floating panel.
M4 Culling + comfort: widen the game's cull, smooth the camera, set scale.
M5 Talking: hold the trigger and use the headset mic, with live log
   checks like on the phone.

  are SMALL: HYP_VR_SCALE is now 12 units/m by default.

TECHNICAL DESIGN (M1)
A. plume (RT64's Vulkan layer), new patch 0006:
   - VulkanExternalHooks covers: extra instance/device extensions, a
     physical-device picker (from xrGetVulkanGraphicsDeviceKHR), and a
     "device created" callback (instance, physical device, device, graphics
     queue family and index) for XrGraphicsBindingVulkanKHR.
   - Wrap the XR swapchain VkImages with the existing
     VulkanTexture(device, VkImage) constructor.
   - Hold the plume queue mutex around xrEndFrame, which uses the queue.
B. src/vr/ (HYP_VR builds only):
   - OpenXR instance (XR_KHR_vulkan_enable), session, LOCAL/STAGE space.
   - One swapchain per eye, xrWaitFrame/BeginFrame/LocateViews/EndFrame.
C. RT64 hooks:
   - WorkloadQueue::threadRenderFrame already takes a camera per call.
     Render each display frame twice, one per eye, into two override
     targets (the same mechanism as interpolated frames).
   - The projection processor gets a VR path for perspective projections:
       view = interpolated game view * inverse(eye pose, metres scaled to
              N64 units)
       proj = asymmetric frustum from XrFovf, near/far taken from the
              game's own projection
     Both RT64 and OpenXR treat -Z as forward and +Y as up, so the axes
     already match.
   - The present thread blits each eye target into its XR swapchain image
     instead of the window swapchain. The XR frame loop sets the pace.
D. Build: a HeyYouPikachuVR target with the OpenXR loader (from the SDK
   source on Windows, the prebuilt .so on Quest).
E. Test: the PC build under the simulator, on a hidden desktop, at 5%
   volume. Then the Quest APK, sideloaded.
